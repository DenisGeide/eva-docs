# Как обновлять документацию

Пишите для человека, который впервые слышит о Еве. Сначала объясните смысл, затем технический термин. Отдельно обозначайте текущую возможность, исторический результат, ограничение и план.

## Перед изменением

- Найдите подтверждение в актуальных правилах и реализации.
- Для цифры сохраните период, часовой пояс, поле, смысл и границы охвата.
- Не называйте реестр числом отвеченных диалогов, а все заказы — завершёнными продажами.
- Реальную переписку замените явно вымышленным примером. Обезличенный пересказ не должен сохранять узнаваемые детали человека.
- Изображения проверяйте глазами и по метаданным. При сомнении исключите изображение.

В `.gitignore` задан разрешающий список. Новые вложения нужно отдельно проверить и явно разрешить. Никогда не используйте `git add -f` для обхода этой защиты.

## Приватность

Не добавляйте credentials, рабочие конфиги, source-код приложения, DB/dumps/backups, реальные customer ID, контакты, частные адреса и абсолютные пути. Не переносите целиком внутренний отчёт даже ради удобного цитирования.

Порядок проверки: [privacy-review.md](privacy-review.md). Не размещайте найденный секрет в публичном issue; используйте согласованный закрытый канал связи с владельцем.

## Проверка структуры

У каждой содержательной страницы есть «Назад · Содержание · Далее». Относительные ссылки должны открываться из README. Схемы используют Mermaid, примеры — понятные учебные сущности без production-идентификаторов.

В этом репозитории нет инструкций подключения к рабочей Еве. Его Git-операции относятся только к документации.

## Связать чистую локальную папку и сделать первый push

Следующие команды предназначены для **новой подготовленной папки документации**, где ещё нет Git-истории и remote. Перед ними нужно проверить весь будущий снимок.

```powershell
git init --initial-branch=main
git add .
git diff --cached --stat
git status --short
git commit -m "docs: publish EVA documentation"
git remote add origin https://github.com/DenisGeide/eva-docs.git
git push -u origin main
```

Если `origin` уже существует, вместо `remote add` используйте `git remote set-url origin https://github.com/DenisGeide/eva-docs.git`. Не используйте force-push для замены чужой истории. Доступ к GitHub настраивается штатной авторизацией, без токенов в URL, файлах или командах.
