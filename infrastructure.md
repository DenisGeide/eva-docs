# Инфраструктура без секретов

Ниже — роли компонентов, подтверждённые исходниками и правилами проекта. Это не инструкция развёртывания production и не снимок всех запущенных сейчас процессов.

## Основные части

| Компонент | Зачем нужен | Существенная граница |
| --- | --- | --- |
| PostgreSQL | Основное хранилище рабочего состояния | Старый архив SQLite не заменяет актуальные данные |
| Приложение и интерфейс | Связывают диалоги, товары, заказы и контроль владельца | Открытие интерфейса не разрешает отправку |
| Ollama | Запускает установленную локальную языковую модель | Доступность сервиса и загруженной модели проверяется отдельно |
| Gemma | Локальный модельный путь понимания/подготовки ответа | Фактическая модель определяется настройками установки |
| Codex | Участвует в настроенных сценариях автора, проверки и разбора затруднений | Не является безусловным обходом guard или локальных прав |
| Worker | Исполнитель ограниченной задачи | Старый статус работы не доказывает, что worker активен |
| Watchdog | Проверка прогресса и зависших задач | Не подменяет подтверждение результата |
| Supervisor companion | Поддерживает дочерний companion-процесс приложения | Не является универсальным менеджером всех процессов ПК |
| Планировщики синхронизации | Получают сообщения, заказы, состояния и выполняют проверки | Независимые циклы не означают разрешение дублировать полный обход |
| Штатные резервные копии | Сохраняют проверяемый снимок актуального состояния | Восстановление — отдельная согласованная операция |

## PostgreSQL и совместимость

С 02.11.2026 PostgreSQL указан как основной источник рабочего пространства. В коде есть слой совместимости с прежними вызовами хранилища, поэтому старые имена интерфейсов не доказывают использование старой SQLite-базы.

При недоступности основной БД нельзя молча продолжить работу на устаревшем архиве. Резервное копирование и восстановление должны сохранять текущее состояние, связи, попытки и защитные факты, а не возвращать историю «как было удобнее».

## Модель и внешние зависимости

Локальный путь использует Ollama/Gemma; в прочитанном runtime есть восстановление установленного Ollama при определённых ошибках соединения. Название модели по умолчанию в исходнике не равно доказательству, что именно этот экземпляр сейчас загружен.

В проекте также есть интеграция Codex. Поэтому обещание «во всех режимах всё обрабатывается только локально» было бы неверным. Поток контекста зависит от включённого маршрута; секреты не должны попадать в публичную документацию.

## Несколько независимых циклов

- **Свежие обращения:** приоритетная очередь ответов.
- **История:** ограниченные пакеты известных диалогов с долговременным охватом и ошибками.
- **Заказы:** штатная синхронизация заказа и его статусов.
- **Остатки:** ежедневная сверка с общим слотом, чтобы два инициатора не создали второй полный обход.
- **Наблюдение:** реальные свежие действия, активность и квитанции.

Успешный checkpoint обновляется после успешной проверки. Ошибка не должна выдавать непроверенную историю за актуальную.

## Что нужно для работы ночью

Запущенные программа и необходимые сервисы, работающий компьютер, доступные подключения, разрешённый режим и ресурсы для модели. После перезагрузки нужен штатный запуск или заранее настроенный автозапуск. Долговременное состояние помогает продолжить, но не включает выключенный ПК.

Здесь намеренно нет адресов инфраструктуры, портов, имён учётных записей, значений конфигурации, переменных с секретами и команд доступа к рабочим сервисам.
